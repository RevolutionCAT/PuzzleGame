general concept:
- there will be 6-10 bars. 
- the user will move the bars to get an idea of what algorithm is guessed.
- after moving the bars, the user will click submit button. after this, the game will reveal what is correct or not.
- the game will allow only limited amount guesses.
- there will be a "dictionary" of algorithms that will include all info about them AND visualization of them.



general possible problems to solve:

- the amount of guesses is intended to stay limited, however it is impossible since some algorithms may have too much of them
- the game is too solvable. after the user guesses the first iteration, they most likely know what algorithm it is.
- do bar values for iteration reveal too much? do we still need them if one of the ideas accepted will work perfectly?
- if the user knows what algorithm is guessed exactly, how do they actually guess this algorithm? its not a good design if
  the user will have to build all the exact steps no matter how long the algorithm is.



possible fixes of the general problems:

- ignore it and set the max amount of guesses regarding the algorithm? this is because it wont really help the user to guess the
  algorithm if they have 20 attempts available. it makes the game unfair and eventually too solvable if the attempts stay 
  unlimited. thus the amount of guesses is fine to keep around 8, counting the right guess as a guess too, no exceptions.
- it may be ignored ONLY if there are too many similar algorithms, because after first iteration there are still options to 
  choose from. otherwise this is most likely a massive issue.
- ? however, it depends on the idea used in the end.
- e.g. can implement a window that lists all the available algorithms for the current difficulty/mode, and the user will choose

============================================ more focused ==================================================


idea 1:

- after every submit, the puzzle will be reverted back to its initial unsorted state. = similar to worlde, since
  after one guess you are back to the empty space.
- the player's guess will be visually moved somewhere e.g. upwards (and made smaller) so that the player does not forget
  what they just guessed. = similar to worlde.

Problems:
- the game will not check iterations. instead it will check something else? because it becomes impossible to compare iterations,
  since the game is reversing the puzzle back to its unsorted state
- thus you cannot really reveal the values of the bars, since there are no iterations.




idea 2: 

- idea 1 but with this addition + some problem fix:
- after the exactly correct guess of the iteration, the game will revert the puzzle not to unsorted state, but to the state
  exactly after the first iteration ended. = it is still similar to wordle, since the game is going back to some previous state
  whatsoever.
- same iteration thing will be applied to all the further iterations.
- visually, it will be told what iteraion the puzzle goes back to. 

Problems: 
- previous user guesses become useless after the game reverts the puzzle to somewhat-sorted state.
